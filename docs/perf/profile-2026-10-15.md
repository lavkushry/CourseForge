# CPU profile findings — anonymous read load (2026-10-15)

Status: measured on a 10k-VU-style anonymous catalog/feed read load against a
2 vCPU / 1 GB API process. Percentages are cumulative share of the profiled
samples, not wall-clock exclusive time.

## Hot spots

| Symbol / area | ~cum | Cause |
| --- | --- | --- |
| `api.(*Server).homeFeed` | 23% | Postgres on every request (featured cards + trending + optional continue); `map[string]any` JSON via reflection |
| `api.(*Server).trendingItems` | 13% | Same trending SQL as home-feed, uncached; map-shaped rows |
| `pgxpool` `Query` | 17% | Uncached catalog/feed SQL under concurrent VUs |
| `/health/ready` DB ping | 5% | `Pool.Ping` on every readiness probe |
| `httpx.JSON` / `encoding/json` | 10% | Re-encoding `map[string]any` / interface values per response |
| socket read/write | remainder | Expected under high concurrency once app work drops |

## Fixes applied (Phase 9)

1. **Anonymous feed cache** — Cache only the anonymous/public `home-feed` and
   `trending` variants under `catalog/public/...` keys (query-string encoded),
   same TTL store as public courses. Authenticated home-feed stays uncached
   (continue-watching + enrollment personalization). `invalidateCatalog` still
   deletes the `catalog` prefix on publish/catalog writes.
2. **Pre-encoded JSON + CDN-friendly headers** — Cache stores marshaled bytes;
   hits write those bytes without re-encoding. Anonymous public catalog/feed
   responses send `ETag`, honor `If-None-Match` with `304`, and
   `Cache-Control: public, max-age=30, stale-while-revalidate=60`. Personalized
   responses remain `Cache-Control: no-store`.
3. **singleflight** — Concurrent misses for the same cache key collapse to one
   build+marshal+`Set`.
4. **Readiness ping cache** — `/health/ready` reuses the last DB ping for 1s;
   `/health/live` stays a trivial process liveness check.
5. **Typed hot-path payloads** — `HomeFeedResponse`, `TrendingResponse`,
   `PublicCoursesPage`, `PublicCourseDetail` (and private course page structs)
   replace `map[string]any` on the read paths above.
6. **Indexes** — EXPLAIN on an isolated migrated test schema with a growth
   fixture (~2k courses, 20k lessons, 200k `playback_totals`):

   - **homeFeed** `WHERE published ORDER BY id LIMIT 30` already uses
     `courses_catalog` (index-only style); no new courses index.
   - **trending** 7-day `playback_totals` aggregate: seq scan ~6.7ms / cost 576
     → bitmap via `playback_totals_recent_watched` ~3.0ms / cost 260.
     Added in migration `021_feed_perf_indexes.sql`.

## Remaining

Socket syscall time dominates once cache hits are warm; further gains are
horizontal replicas, Redis shared cache (`REDIS_URL`), and keeping load-balancer
health checks on `/health/live` when full readiness every probe is unnecessary.
