# CourseForge UI audit

The audit covers **415 screenshots, 83 views/state variants, all five widths, and 40 findings.** The original evidence is preserved below. Final implementation and verification are documented in [UI_LAYOUT.md](UI_LAYOUT.md), [UI_COMPONENTS.md](UI_COMPONENTS.md), and [UI_VALIDATION.md](UI_VALIDATION.md).

The owner authorized completing all four stages without approval stops on 2026-10-11. The replacement attachment repeats the same scope and adds emphasis on element placement, buttons, text fields and sizes.

Production source baseline: `e4db474`. The actual 11-course catalog is rendered in a disposable SQLite backup after removing all private account/runtime records. Audit administrator and learner accounts, notes, bookmarks and educational assessment fixtures exist only in that backup. No production QA accounts are created.

Widths: **320, 390, 768, 1366, 1920 px**, 900 px viewport height. The [screenshot gallery](ui-evidence/stage-1/index.html), [geometry and computed controls](ui-evidence/stage-1/measurements.json), [capture manifest](ui-evidence/stage-1/manifest.json), and [complete token ledger](ui-evidence/stage-1/token-ledger.json) supply the evidence.

Baseline full-page captures can show lazy content that has not rendered outside the viewport. Final captures warm lazy image and lesson content for complete evidence; focused captures show the lesson rail, materials, notes, bookmarks, planner, focus and forms after scrolling them into view. Deliberate failures are browser-scoped responses. The seeded assessment response exercises the real question renderer and the real server grading endpoint.

The requested user-tracking modal is implemented in this revision as the administrator student-detail page, `#admin/students/<id>`. That existing screen is audited; this pass does not add a new modal.
